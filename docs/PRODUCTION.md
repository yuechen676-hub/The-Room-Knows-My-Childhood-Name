# 游戏资产制作与场景整合

[文档目录](README.md)

## 围绕观察和操作制作物件

房间中的物件既构成童年卧室的视觉风格，也承担拿起、翻看、开合和播放声音等操作。制作时需要同时考虑远处的轮廓、近看的表面细节，以及玩家能够实际触碰的位置。

制作链路为 Blender / 图像处理 → 模型、贴图与可动部件导出 → Unity 材质和组件配置 → 场景中的交互检查。模型进入引擎后，需要调整尺寸、朝向、材质槽、轴心与碰撞，确保视觉和操作使用同一个空间基准。

## 可动部件与观察细节

水壶盖、听筒、柜门和抽屉分别需要独立层级和合理轴心。组件控制局部动作，物件查看系统负责整体拿起和旋转，避免查看姿态覆盖部件自身的开合状态。

近距离查看还决定了贴图的制作要求：书脊文字、纸面、相框图片和杯底细节需要在实际阅读距离下检查。修改模型或 UV 后，应同步复核点击位置、观察角度与记录绑定。与叙事有关的细节还受阶段条件控制；普通陈设的可操作性不自动增加通关条件。

## 程序化房间与材质

当前房间外壳采用程序化几何，天空采用项目的程序化天空 Shader；当前这两部分未使用第三方环境素材包。墙体、门窗、地面与天花板由构建工具生成，并同步碰撞和交互几何。

外壳纹理由离线 Python 脚本生成周期噪声，再输出颜色和法线贴图。固定随机种子便于重复生成，参数控制不同表面纹理的频率与方向。游戏运行时直接加载生成结果。具体算法见[程序化制作工具](TOOLS.md)与[天空系统](SKY.md)。

## AIGC 辅助贴图产出

部分插画与贴图采用 AIGC 辅助，以个人绘画风格为基础生成候选图，经过人工筛选、构图调整和材质适配，用于相框、柜体等场景物件。生成发生在制作阶段，游戏运行时加载已整理的图片。

## 声音制作与接入

孩子的声音使用 ElevenLabs 预先制作后导入；线索伴随声与环境声由作者录制，部分补充操作音由脚本合成。录音、字幕和物件绑定分别组织，使语言显示和声音播放能够协调工作。

音频接入需要检查触发、重复播放、字幕时机和场景转场。阶段环境声采用 Streaming 导入，配合淡入淡出，减少切换时的解码停顿；这一调整的定位过程见[性能分析](PERFORMANCE.md)。

## 工程组织与迭代检查

运行时逻辑位于 `Assets/Scripts`，主要编辑器工具位于 `Assets/Editor`，实时对话服务位于 `Deployment/server`。资源迁移时保留 `.meta` 与 GUID 关系，避免场景和组件引用失效。

每次资产更新依次检查外观与文字可读性、可动部件轴心、点击与碰撞、声音与记录绑定，再检查阶段可见条件。这样可以在美术迭代中保持玩法稳定。

## 使用的工具与技术

| 环节 | 工具或实现 |
|---|---|
| 游戏与界面 | Unity、C#、URP、Input System、uGUI |
| 模型与图像整合 | Blender、图像处理与制作脚本 |
| 环境表现 | 项目程序化天空、房间外壳和纹理生成工具 |
| 预制声音 | 作者录音、ElevenLabs、操作音合成脚本 |
| 可选联网对话 | Python、Flask、Waitress、Anthropic SDK / API |
| 开发辅助 | AI 辅助编程与部分贴图候选生成，人工整合和测试 |

URP 扩展 Shader 保留所依赖实现的说明。工具、框架和服务与环境素材包分别列示，具体实现见各技术章节。
