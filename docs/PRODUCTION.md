# 制作流程与资产来源

[文档目录](README.md)

## 从素材到可交互物件

制作链路为 Blender / 图像处理 → 模型、贴图与可动部件导出 → Unity 材质和组件配置 → 检视与场景验证。资产不仅需要视觉完整，还要满足真实尺寸、UV、材质槽、轴心、碰撞与可读文字等约束。

以水壶盖、听筒、柜门和抽屉为例，可动部分需要独立层级与合理轴心，声音和动画再由组件触发。局部模型或贴图更新后还应核对互动位置，不能只检查静态渲染图。

## AIGC 辅助贴图制作

部分插画与贴图采用 AIGC 辅助：以个人绘画风格为基础生成候选图，经过人工筛选、构图与材质适配后，用于相框、柜体等场景物件。人工工作重点是判断风格、选择合适内容并完成游戏中的整合；图像生成属于制作阶段，不在游戏运行时执行。本章不展开底模与训练参数。

## 来源按工作环节区分

| 内容 | 制作或来源说明 |
|---|---|
| 项目模型 | Blender 制作与脚本辅助处理；部分基础形有 AI 辅助来源，最终逐项来源应以资产记录为准 |
| 插画与纹理 | 个人绘画、AIGC 辅助素材与后续适配并存；不将全部导入图像统称纯手绘 |
| 房间外壳 | 程序化几何与周期噪声贴图，见工具章节 |
| 孩子声音 | ElevenLabs 预先制作并导入 |
| 线索伴随声与环境声 | 现有制作记录注明作者自行录制 |
| 补充操作音 | 部分由脚本合成，独立于原始线索录音 |
| 代码 | 开发包含 AI 编程辅助，需求拆解、审阅、测试与实际整合构成制作工作 |
| 历史第三方环境素材 | Will's Room、AllSky、PBR 200 Premium Materials 等有使用记录；后续外壳与天空已有替换 |

不能从“存在 Tripo 插件”推断全部模型由 Tripo 生成，也不能从“重建外壳依赖归零”推断整个项目完全没有第三方资产。现存模型是否全部重拓扑、UV 是否全部重做，未完成逐模型鉴定，因此不使用“全部”作为成果声明。

## 工程组织与可维护性

运行时逻辑集中在 `Assets/Scripts`，编辑器工具在 `Assets/Editor` 及部分资产自身的 Editor 目录，Python 服务在 `Deployment/server`。资源清单与 .meta GUID 关联需要一起保留；改名、迁移和删资源时应检查引用，而非只检查文件能否打开。

本次发布仅上传文档、解释用图例和选定代码快照。训练权重、完整制作源文件、缓存、日志、备份与本机凭据不随文档上传。代码快照保留原有依赖说明，不构成对第三方实现的新许可。

## 资产变更验收

每次模型或材质替换至少核对：外观是否合适，文字是否可读，碰撞与点击是否一致，可动部件轴心是否正确，录音与发现绑定是否仍指向原物件。与叙事有关的实物信息还需检查出现阶段，避免制作流程中的展示截图成为运行时提前泄露的内容。
