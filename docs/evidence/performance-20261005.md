# 房间性能优化第二轮：2026-10-05 至 10-06

## 测量条件

- Windows Development Player，Direct3D12，1920×1080，VSync 关闭，不限帧。i5-13600KF / RX 6750 GRE 12GB。
- 测试包：`Builds/PerformanceProbe/RoomPerformance.exe`，由 `rebuild_probe.sh` 构建；运行入口 `run_round.ps1`。
- GPU 拆解与候选方案均为同一进程内交替切换，固定起点水平旋转一周，预热 2 秒、采样 8 秒；结束后还原，不写入场景。
- 编辑器保持打开，另有一个会话同时操作工程，个别轮次的 CPU 帧耗时和 P95 受后台影响。各结论以同一进程内的成对比较和 GPU 时间为准。
- 不含远程 AI 对话；正式发行包未更新。

## 1. 基线与开销拆解（`gpu-baseline.json`）

| 状态 | FPS | GPU ms | 批次 | 三角形 |
|---|---:|---:|---:|---:|
| 当前设置 | 117.7 | 6.90 | 4,545 | 2,448 万 |
| 关闭三面镜子 | 173.5 | 4.78 | 2,655 | 1,472 万 |
| 关闭点光/聚光阴影 | 154.2 | 5.48 | 3,307 | 1,611 万 |
| 关闭主光阴影 | 136.7 | 6.16 | 3,431 | 1,847 万 |
| 镜子与全部阴影关闭 | 290.0 | 2.85 | 750 | 350 万 |

房间本身每帧约 350 万三角形、750 批次；其余约 85% 的几何量来自镜面重绘与阴影 Pass。

## 2. 阴影参数（`shadow-candidates.json`）

| 方案 | 结果 | 处理 |
|---|---|---|
| A 主光 12 m / 2 级级联 | GPU 时间与批次无可测变化 | 不采用 |
| B 点光阴影分档设为 Low（256） | 无可测性能变化；图集降分辨率警告 14 → 0；四个朝向截图差异 < 0.5% | 待写入场景（见“未完成”） |
| C 小于 20 cm 的物件不投影 | 投影物体 −670，帧耗时在噪声内，重复组 P95 变差 | 不采用 |

## 3. 镜面视锥裁剪（`mirror-candidates.json`）——已采用

`Assets/Scripts/Rendering/PlanarReflectionScissor.cs`：将反射相机投影裁剪到镜面包围盒在屏幕上的矩形，按矩形分配反射 RT（保持原像素密度，32 像素取整，使用临时 RT 池）。五个镜面脚本各改 5 行改为调用它；镜面 Shader 通过 `_ReflectionVP` 投影采样，无需修改。原文件备份：`Backups/MirrorScissor_20261005/`。

| | 全屏反射 | 裁剪 | 变化 |
|---|---:|---:|---:|
| FPS（两轮均值） | 124.7 | 157.2 | +26% |
| GPU 时间 | 6.91 ms | 5.42 ms | −22% |
| P95 帧耗时 | 11.25 ms | 8.00 ms | −29% |
| 批次 | 4,590 | 3,359 | −27% |
| 三角形 | 2,470 万 | 1,820 万 | −26% |

三面镜子的 GPU 开销约 2.1 ms → 0.65 ms。四个朝向截图：差异只在镜面内物体轮廓，原分辨率放大对比内容一致，为亚像素采样差异（`zoom-mirror-3.png`）。

## 4. 逐灯阴影开销（`lights-after-scissor.json`）

主光阴影单项最高：GPU 0.72 ms、−1,084 批次；其余 7 盏各 0.05–0.26 ms。

主光级联复测（`main-shadow.json`，每次设置后读回确认生效）：

| 设置 | GPU ms | 批次 |
|---|---:|---:|
| 4 级 / 50 m（现状，两轮） | 5.37 / 5.25 | 3,362 / 3,359 |
| 1 级 / 50 m | 4.92 | 2,996 |
| 1 级 / 15 m（两轮） | 4.92 / 4.99 | 2,954 / 2,979 |

1 级级联节省约 0.4 ms GPU（−8%）、约 380 批次。代价：墙上窗户月光光斑边缘略软、窗框投影棱角变弱（`zoom-main-3.png`）。属美术取舍，未应用；可再测“1 级 + 4096 阴影图”。

## 5. DX12 渲染状态预热（`pso-*.json`）

用 `GraphicsStateCollection` 记录完整交互路线（193 个状态、82 个变体，`room-d3d12.graphicsstate`），预热耗时 33–43 ms。交替四轮：

| 运行 | >33 ms 帧 | >50 ms 帧 | 最长帧 |
|---|---:|---:|---:|
| 不预热 1 | 28 | 25 | 207.0 ms |
| 预热 1 | 14 | 8 | 95.8 ms |
| 不预热 2 | 13 | 6 | 91.8 ms |
| 预热 2 | 14 | 8 | 86.1 ms |

第二轮不预热与两轮预热结果相当；第一轮的 180–200 ms 长帧分散在多个无关段落，更像后台干扰。`Shader.CreateGPUProgram` 计时全程为 0。**结论：本机无法把长帧归因于 DX12 管线状态编译，不采用预热。** 9 月 30 日“DX12 首次使用渲染状态”的推测不成立。

四轮均稳定复现的长帧：阶段切换 2→3、3→4、4→5、5→6 各一次约 77–95 ms；近看马克杯一次约 86–96 ms。属于内容侧可定位的卡顿，为下一步重点。
