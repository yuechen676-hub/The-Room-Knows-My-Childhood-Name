# 开发迭代与后续计划

[文档目录](README.md)

## 从问题出发选择技术

项目的开发重点是让探索、表达和环境变化形成连续体验。技术方案不仅需要能够运行，还需要保留文字可读性、物件操作和逐步揭示的节奏。以下整理了我在机器学习、渲染和资源优化中尝试过的方案，以及保留或撤回它们的原因。

| 开发问题 | 尝试与结果 | 当前取舍 |
|---|---|---|
| 如何理解自由输入 | TF-IDF + Logistic Regression 四分类原型；307 条留出样本中 252 条正确，82.1% | 单句分类难以表达阶段和证据关系，改用模型结构化评估与服务端规则，见 [AI 叙事](NARRATIVE.md) |
| 镜面重复渲染成本 | 按镜面屏幕范围裁剪反射目标；同轮测试 124.7 → 157.2 FPS，GPU 6.91 → 5.42 ms | 保留裁剪、尺寸分桶与目标池，见[性能分析](PERFORMANCE.md) |
| 高面数小物件 | 自动 LOD 与连通分量保护；书脊文字受损，保护后减面收益约 3%，没有可测 GPU 收益 | 撤回自动 LOD，按物件评估文字和轮廓 |
| 阶段切换卡顿 | 定位环境声首次播放的解码停顿 | 阶段环境声改为 Streaming，并保留淡入淡出 |
| 着色器首次使用停顿 | 尝试 PSO 预热，未获得可靠改善 | 不将预热计入已实现的性能收益 |
| 无 API 环境如何试玩 | 将固定对话分支录制为数据，按已获得的信息过滤选项 | 离线试玩与可选联网模式共用探索和阶段表现系统 |

分类器数字来自 AI 生成语句的保存评估，不代表真人测试准确率；性能数字对应各章节标注的开发版本、硬件和采样条件。这些实验共同形成了当前的实现选择。

## 后续开发重点

**完整体验检查。** 从标题到结尾完成图形模式试玩，检查中英文、物件翻看、提示、暂停和阅读确认，以及主动开门与离开；在没有开发环境的机器上验证解压运行。

**稳定性与性能。** 复查行走、铁罐交互和音频首次播放时的长帧。在相同构建、视角和采样条件下比较 GPU 时间、P95 与最长帧，避免平均帧率掩盖局部停顿。

**对话体验。** 用真实玩家的表达补充测试样例，观察自然输入是否被正确理解、提示是否足够明确，以及联网错误后的重试体验。新增对话内容需要保持现有阶段的信息边界。

**工程维护。** 在 Unity 中复查场景脚本引用、模型导入参数和资源绑定，固定构建清单与回归流程。公开的代码摘录用于讲解实现，不是完整可构建工程。

以上是待推进事项。已完成检查与测试范围集中记录于[验证报告](VALIDATION.md)。
