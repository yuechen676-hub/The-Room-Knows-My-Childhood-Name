# AI 叙事系统：自由表达与阶段规则

[文档目录](README.md) · 本页包含叙事结构与推进细节。

## 为什么不让模型直接控制游戏

玩家可能用关心、质疑、试探或不完整的表达接近主题。纯关键词匹配容易要求玩家猜出开发者的措辞；完全让模型决定阶段，又可能在证据不足时提前推进或揭露后续内容。

我将自然语言解释与推进控制拆开：模型负责理解表达，服务端保存阶段状态并检查条件。模型提供回复与结构化评估，Python 核对引用、已听录音、已见事实和本阶段要求，再决定是否更新阶段。规则可以拦截不满足条件的推进；语义理解的准确性仍需要通过实际对话评估。

## 一次输入如何经过系统

| 步骤 | 数据与处理 |
|---|---|
| Unity 收集 | text、language、recovered_memories、discoveries 与 session_id |
| 服务整理 | 当前阶段、近期对话、合法证据与提示词 |
| 模型返回 | 文本回复、理解评估、证据引用和回应引用 |
| 规则检查 | 引用是否存在于实际发言 / 回复，线索是否已发现，阶段条件是否满足 |
| 状态保存 | 保留已经取得的理解；模型失败不凭空推进 |
| 客户端展示 | 展示回复，阶段完成后等待阅读确认，再改变环境表现 |

后端使用不同阶段评估器：stage_one、stage_two、later_stages。历史分数或轮数不能单独成为通关依据。模型上下文只传允许使用的发现；程序不信任客户端提交的任意“细节解释”，而是依据合法发现标识组织已知事实。

## 情绪约束如何进入技术条件

底层事实是孩子用安慰性说辞保护自己、回避现实，但早期不要求完整承认“我在撒谎”。第一阶段可以接受玩家察觉安慰的需要；第二阶段接受对说辞与实物冲突的局部让步；后期才逐渐增加揭示力度。

同阶段探索顺序自由。先表达有效理解、后补齐录音时，理解不应丢失；反过来，听完录音也不自动等于理解。测试覆盖“全部录音 + 问候不能推进”“提前理解可保留”“虚构引用不能取得理解”等情形。

## 失败与重试

结构不合法、引文不在原始输入、或部分阶段回应违背约束时，服务代码有针对性重试。仍无法获得有效结果时返回可重试错误并保留已取得的进展，不能把服务失败当作剧情沉默或完成。

旧聊天历史与玩家当次输入区分处理，避免把此前的模型评估 JSON 当作当前玩家发言的证据。上下文截取控制长度，但服务器内存会话不是持久化存档；服务重启后无法承诺恢复。

客户端 HTTP 超时设为 125 秒，服务端模型客户端配置为 45 秒且 SDK 自动重试关闭。应用级重试可能增加总等待时间，实际响应时间还取决于网络和模型服务。

## 服务接口与资源边界

serve.py 的包装包含 X-Room-Token 验证、16 KB 请求体限制、会话锁、最多两个并发生成容量、默认每小时 120 次计数和最多 32 个会话；清理会话的空闲阈值为两小时。健康检查可独立公开，但不会因此开放游戏接口。

上述限制用于控制单个服务进程的资源占用，实际负载能力尚待测试。会话存于内存，没有多进程共享持久化。试玩采用离线模式，因此不依赖这套服务在线。

## 从独立分类器到当前方案

我最初尝试用 TF-IDF + Logistic Regression 构建四分类原型，标签为 accepting、questioning、recognizing、rejecting。保存的资料记录 1,228 条 AI 生成标注语句，75% / 25% 分层划分，307 条留出测试中 252 条正确，即 82.1%；五折交叉验证记录为 81.2%，标准差 2.8 个百分点。

在开发过程中，我发现单句态度分类难以处理玩家已经获得的线索，以及连续交流中逐渐形成的理解。因此，我没有将分类器作为最终推进判定，而是转向结合阶段、证据和近期对话的模型评估，再由服务端检查推进条件。

82.1% 对应 AI 生成语句的留出测试。早期志愿者语句未保留下来，因此这项结果不包含真人数据评估；两种方案也尚未进行真人对照实验。

分类器数据来自保存的实验记录，未重新训练旧模型。开发工程中的过程笔记为 `SubmissionPlanning/classifier-process-notes.md`。

## 离线版如何保留这些约束

离线录制在真实会话的分支上进行，只向服务提供该选项出现时必然已经获得的信息。运行时按同样的可见条件显示选项，再回放对应回复和 closes 判定。它不在线理解自由输入，也不覆盖所有可能回复。

当前离线数据包含 54 条台词定义与 77 个文字回复变体。详见[离线对话与接口](DIALOGUE.md)。

错误路径使用无效输出和连接失败等模拟响应，检查服务能否保留进展并返回可重试错误。真实模型的叙事表现与 Unity 完整试玩需要另外验证，详见[测试报告](VALIDATION.md)。
